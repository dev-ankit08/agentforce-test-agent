Title: Order Status & Returns Agent

As a customer contacting support through the Agentforce chat widget, I want
to ask about my order status, check whether an item is eligible for return,
and start a return, so that I can resolve simple order issues myself without
waiting for a human agent.

Acceptance criteria:

1. Given a valid order number or the email address on the order, the agent
   looks up the order and states its current status (e.g. processing,
   shipped, delivered) along with the shipment/delivery date if available.

2. Given an order number, the agent checks return eligibility using the
   actual purchase/delivery date on that order: items are eligible for
   return within 30 days of delivery, and not eligible after that window.
   The agent must state the specific reason when a return is not eligible.

3. When an order is eligible for return and the customer confirms they want
   to return it, the agent initiates the return and provides the real
   return authorization number generated by that action.

4. If the customer provides an order number that does not exist in the
   system, the agent must say it cannot find that order and ask the
   customer to double check it or offers to escalate -- it must never
   invent an order status, shipment date, or return authorization number
   for an order it could not actually retrieve.

5. If the customer explicitly asks to speak to a human, or asks something
   outside order status/returns (billing disputes, account changes,
   general company questions), the agent escalates to a human agent rather
   than guessing or answering from outside its scope.

6. The agent must never state any order fact, return eligibility decision,
   return authorization number, or policy detail unless it was actually
   returned by a system action in that conversation. No fabricated data,
   ever, under any phrasing of the request.
